# Session Summaries

This folder is the concise conversation memory for the project. It supplements
the authoritative project register; it does not replace it.

## Rules

- Create one dated summary for every meaningful work session.
- Record decisions, implementation work, test results, blockers, commits, and
  the exact next action.
- Link the related entries in `docs/PROJECT_STATE.md` and, when testing is
  involved, `docs/LIVE_E2E_TEST_REGISTER.md`.
- Never record passwords, API keys, database connection strings, personal
  data, or raw chat transcripts.
- Update the two authoritative registers in the same commit as any project
  change. A session summary is a handoff aid, not an alternative source of
  truth.
